# Prepend Oracle 題目筆記（40002）

## 題目流程

服務可以重複接收我們指定的 `message`，並回傳下列資料的 AES-ECB 密文：

```text
message || FLAG || 補零至 16 bytes 的倍數
```

`message` 在送出前要轉成十六進位。每次查詢都使用同一把金鑰，所以相同的 16-byte 明文區塊會得到相同的密文區塊。我們可以用這個特性，把 FLAG 一個 byte 接著一個 byte 猜出來。

## 先量出比較長度

查詢空訊息 `oracle(b"")`，密文長度是 **48 bytes**。這代表 FLAG 加上補零後占 3 個 AES 區塊；48 不是 FLAG 真正的長度。

## 猜第一個 byte

送出 47 個 `A`，待加密的明文開頭會是：

```text
47 個 A || FLAG[0] || FLAG[1] ...
```

`FLAG[0]` 因此位於前 48 bytes 的最後一格。再測試 `47 個 A || 猜測 byte`，逐一比較兩次密文的**前 48 bytes**。兩者相同時，就找到了 `FLAG[0]`。

不需要解密：ECB 對相同區塊會產生相同密文，因此密文相同即可用來比對猜測。

## 逐 byte 推進

已知第一個 byte 後，改送 46 個 `A`，使 `FLAG[1]` 再次落在第 48 格：

```text
目標：46 個 A || 真正的 FLAG[0] || 真正的 FLAG[1] || ...
測試：46 個 A || 已知的 FLAG[0] || 猜測 byte
```

依此類推，每得到一個 byte，就少送一個 `A`，並把已知的 FLAG 接在 `A` 後面。猜測範圍用 `0..255`，才能涵蓋任何 byte，包括換行與補零。

## 終端機互動範例：猜第一個 byte

這是同一次連線的實際數值。`message =` 後要輸入**十六進位**：`41` 代表字元 `A`，`50` 代表 `P`，`58` 代表 `X`。下面第一個 `message =` 是直接按 Enter；後面三次查詢的服務密文都超過 48 bytes，所以只列出用來比較的前 48 bytes。

```text
$ nc 10.99.70.3 40002

cipher = 4ec235e1476db5fba22dd6b9c02640ca2aff38bb03b2aaaf878fda5e13573506fc1a214db856f75e0ce0bcffacdbdb98

message = 4141414141414141414141414141414141414141414141414141414141414141414141414141414141414141414141
cipher 的前 48 bytes = 2854aa5cf3d0f98249c82e37ae6615d52854aa5cf3d0f98249c82e37ae6615d5f16250a38709a174b06cc98734d7e8e7

message = 414141414141414141414141414141414141414141414141414141414141414141414141414141414141414141414150
cipher 的前 48 bytes = 2854aa5cf3d0f98249c82e37ae6615d52854aa5cf3d0f98249c82e37ae6615d5f16250a38709a174b06cc98734d7e8e7

message = 414141414141414141414141414141414141414141414141414141414141414141414141414141414141414141414158
```

第二、三次輸入分別是 `41` 重複 47 次後接 `50` 或 `58`。猜 `P` 的密文與目標前 48 bytes 完全相同；猜 `X` 時最後一個區塊不同，所以第一個 FLAG byte 是 `P`。服務實際會印出完整的密文（此處是 96 bytes），表格僅摘錄前 48 bytes；上面的 `〔...〕` 與「`cipher 的前 48 bytes =`」都是筆記標註，**不是終端機實際顯示或要輸入的文字**。服務每次重啟會換金鑰，密文數值也會變；比較必須在同一次連線內進行。

若用腳本跑完整流程，會看到逐步還原的輸出，例如：

```text
Ciphertext length: 48 bytes
1/48: "P"
2/48: "PH"
3/48: "PH{"
...
FLAG: PH{3Xh4u57iv3_0nE_By735_@t_4_7ime!}
```

提示檔 `40002_hint.py` 的空格可填：

```python
cipher_length = len(oracle(b""))
guess_range = 256
message = prepend + FLAG + bytes([exhaustive])
```

每輪的 `target = oracle(prepend)[:cipher_length]` 是真正的參考密文；`oracle(message)[:cipher_length]` 則是目前猜測的密文。

## 結果與觀念

實測取得：

```text
PH{3Xh4u57iv3_0nE_By735_@t_4_7ime!}
```

FLAG 文字後還有一個換行，接著是 12 個補零 bytes。那是檔案內容及程式補齊區塊的結果，不屬於旗標文字。

**核心問題：**服務允許攻擊者選擇秘密前面的明文，並反覆查詢使用同一把金鑰的 ECB 加密結果。調整前綴長度後，就能用密文相等與否逐 byte 測試秘密。
